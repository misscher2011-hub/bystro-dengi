# Запуск «Быстро Деньги» на Reg.ru + GitHub + Vercel + Neon

Ваш стек идеально подходит для этого сайта: Vercel создан командой Next.js,
Neon — это серверless PostgreSQL, который не нужно администрировать.
Оба имеют бесплатный тариф, достаточный для старта.

Роли участников:

| Сервис | Что делает |
|---|---|
| **Reg.ru** | Домен `dengi-bystro.online` — просто указывает на Vercel |
| **GitHub** | Хранилище кода; каждый push = автодеплой |
| **Vercel** | Хостинг + сборка + HTTPS из коробки |
| **Neon** | База данных PostgreSQL в облаке |

## Шаг 0. Положите код на GitHub

### Вариант А: через сайт (без командной строки)

1. Зайдите на [github.com](https://github.com) → Sign up / Sign in.
2. Нажмите **+** в правом верхнем углу → **New repository**.
3. Имя: `bystro-dengi`. Видимость: **Private** (в коде есть бизнес-логика).
   Ничего не отмечайте (README, .gitignore, license) — файлы уже есть.
4. **Create repository**.
5. На открывшейся странице скопируйте команду из блока
   «…or push an existing repository from the command line».
6. В папке проекта выполните:

```bash
git init
git add .
git commit -m "Быстро Деньги: первый релиз"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/bystro-dengi.git
git push -u origin main
```

> Если сайт был прислан архивом — распакуйте его, перейдите в папку
> с `package.json` и выполняйте команды там.

### Проверка, что секреты не попали в репозиторий

Файл `.gitignore` уже настроен и **исключает `.env`**. Убедитесь, что в списке
коммита нет `.env`:

```bash
git ls-files | grep -E "^\.env" || echo "OK: .env не закоммичен"
```

Ключи эквайринга будут вводиться только в панели Vercel — так безопаснее.

## Шаг 1. Создайте базу в Neon

1. Зайдите на [neon.com](https://neon.com) → **Sign up** (удобно через GitHub).
2. Проект создастся автоматически. Если нет — **Create project**.
   Имя: `bystro-dengi`. Регион: **Europe (Frankfurt)** — ближе всего к России.
3. Откройте **Dashboard** → панель **Connection string** → выберите
   **Pooled connection** (это важно!) → **Copy**.

Строка выглядит так:

```
postgresql://neondb_owner:ПАРОЛЬ@ep-имя-регион-pooler.region.aws.neon.tech/neondb?sslmode=require
```

**Что важно знать:**

- Обязательно берите вариант **Pooled** — в нём есть `-pooler` в имени хоста.
  Это повышает лимит соединений с ~100 до 10 000, что критично для serverless.
- Суффикс `?sslmode=require` — оставьте, без него соединение не установится.
- Сохраните строку в менеджер паролей: она даёт полный доступ к базе.
- Этот сайт использует драйвер `node-postgres` (`pg`) с пулом соединений —
  это **официально рекомендуемый способ** для Vercel Fluid compute.
  Никаких специальных драйверов Neon ставить не нужно.

### Таблицы создавать не нужно

Проект умеет создавать схему сам: при первом открытии сайта на пустой базе
приложение само создаст все 8 таблиц и заполнит демо-данными
(см. `src/db/bootstrap.ts`). Ничего запускать вручную не требуется.

## Шаг 2. Деплой на Vercel

### 2.1. Импорт проекта

1. Зайдите на [vercel.com](https://vercel.com) → **Sign up with GitHub**.
2. **Add New…** → **Project**.
3. Найдите репозиторий `bystro-dengi` → **Import**.
   Если его нет — **Adjust GitHub App Permissions** и дайте доступ.
4. **Framework Preset** подхватится сам: `Next.js`. Ничего не меняйте в
   Build Command / Output Directory / Install Command.

### 2.2. Переменные окружения — главный шаг

До нажатия Deploy раскройте **Environment Variables** и добавьте:

| Key | Value | Notes |
|---|---|---|
| `DATABASE_URL` | строка из Neon (**Pooled**) | Обязательно |
| `YOOKASSA_SHOP_ID` | — | Пока можно пропустить |
| `YOOKASSA_SECRET_KEY` | — | Пока можно пропустить |
| `TBANK_TERMINAL_KEY` | — | Пока можно пропустить |
| `TBANK_PASSWORD` | — | Пока можно пропустить |

> Правая колонка **Environments** должна включать
> Production, Preview и Development — тогда переменная будет доступна и на сборке.

**Без `DATABASE_URL` деплой упадёт** — код подключения к БД проверяет его на
старте. Это первый пункт диагностики, если что-то не работает.

### 2.3. Deploy

Нажмите **Deploy**. Сборка занимает 1–2 минуты.

После окончания Vercel покажет адрес вида
`bystro-dengi-xxxxx.vercel.app`. Откройте его — сайт должен работать,
база заполнится демо-данными.

## Шаг 3. Подключите домен dengi-bystro.online

### 3.1. В Vercel

1. Откройте проект → **Settings** → **Domains**.
2. Введите `dengi-bystro.online` → **Add**.
3. Повторите для `www.dengi-bystro.online` → **Add**.
4. Vercel покажет нужные записи и подскажет, если что-то не так.

Рекомендуемый вариант — направить домен через **A + CNAME**, оставив DNS в Reg.ru.
Значения Vercel покажет на карточке домена. Наиболее частые:

| Тип | Имя | Значение |
|---|---|---|
| `A` | `@` | `76.76.21.21` |
| `CNAME` | `www` | `cname.vercel-dns.com.` |

> ⚠️ **Обязательно сверяйтесь с карточкой домена в Vercel.** У новых проектов
> Vercel выдаёт индивидуальный IP (например `216.198.79.1`) и персональный
> CNAME-таргет вида `d1d4fc829fe7bc7c.vercel-dns-017.com`. Карточка —
> источник истины, старые значения `76.76.21.21` / `cname.vercel-dns.com`
> тоже работают, но Vercel рекомендует новые.
>
> Альтернатива — делегировать домен на NS Vercel
> (`ns1.vercel-dns.com`, `ns2.vercel-dns.com`): тогда A-записи не нужны.
> Но если на домене планируется почта Reg.ru, оставьте DNS в Reg.ru
> и используйте A + CNAME.

### 3.2. В личном кабинете Reg.ru

1. [reg.ru](https://reg.ru) → авторизация → **Мои домены** →
   клик по `dengi-bystro.online`.
2. Блок **«DNS-серверы и управление зоной»** → **Изменить**.
3. Убедитесь, что стоят DNS-серверы Reg.ru: `ns1.reg.ru` и `ns2.reg.ru`.
   (Если выбраны «DNS-серверы хостинга» — ресурсные записи настраиваются
   в панели хостинга, не в кабинете.)
4. В блоке **«Ресурсные записи»** → **Добавить запись** → тип **A**:
   - `Subdomain` = `@`
   - `IP Address` = `76.76.21.21`
   → **Готово**
5. Ещё раз **Добавить запись** → тип **CNAME**:
   - `Subdomain` = `www`
   - `Canonical name` = `cname.vercel-dns.com.`
   → **Готово**
6. Если в списке есть **AAAA**-записи — удалите их, иначе часть посетителей
   будет попадать не туда.

### 3.3. Ожидание и проверка

DNS обновляется от 15 минут до 24 часов (обычно ~30 минут).

```bash
nslookup dengi-bystro.online     # должен вернуть 76.76.21.21
curl -I https://dengi-bystro.online
```

В Vercel на странице Domains статус сменится на
**Valid Configuration** с зелёной галочкой.

### HTTPS — бесплатно и автоматически

Vercel сам выпустит и будет продлевать сертификат Let's Encrypt для
домена и `www`. Ничего устанавливать и настраивать не нужно.

## Шаг 5. Боевые платежи

Когда будете готовы принимать реальные деньги:

1. Оформите магазин в ЮKassa на ваше ИП
   (реквизиты уже заполнены в админке → «Реквизиты ИП»).
2. Получите `shopId` и секретный ключ.
3. Vercel → проект → **Settings** → **Environment Variables** → добавьте
   `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` (Environment = Production).
4. **Redeploy**: вкладка **Deployments** → ⋯ у последнего → **Redeploy**.
   Без этого новые переменные не подхватятся.
5. В кабинете ЮKassa укажите вебхук:
   `https://dengi-bystro.online/api/payments/webhook/yookassa`
6. Проведите тестовый платёж на `/pay` и проверьте его в `/admin/payments`.

Карточки провайдеров в админке переключатся с **ДЕМО** на **LIVE**.

## Диагностика проблем

| Симптом | Причина и решение |
|---|---|
| **Build failed: DATABASE_URL is required** | Переменная не задана или не отмечена для Production |
| **Страницы отдают 500** | Vercel → Deployments → Logs. Чаще всего неверная строка подключения |
| **`prepared statement` / connection errors** | Используется прямая строка вместо **Pooled** — возьмите с `-pooler` |
| **`too many connections`** | Та же причина: нет `-pooler`. Также проверьте, что в `DATABASE_URL` нет опечаток |
| **`SSL connection required` / timeout** | Потеряли `?sslmode=require` в конце строки |
| **`relation "users" does not exist`** | Откройте главную страницу сайта — схема создастся автоматически |
| **Домен не открывается** | A-запись не применилась. Проверьте `nslookup`, удалите AAAA |
| **`www` не работает** | Не добавлен CNAME для `www` в Reg.ru |
| **Ключи не действуют** | Забыли **Redeploy** после добавления переменных |

Логи: Vercel → проект → **Logs** (вкладка Runtime). Ошибки БД видны там.
