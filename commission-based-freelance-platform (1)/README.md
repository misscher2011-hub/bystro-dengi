# ⚡ Быстро Деньги

Биржа фриланса без подписок: заказчик публикует задания бесплатно,
а сервис берёт комиссию только с исполнителя — и только после того,
как тот реально получил деньги.

**Главный оффер:** *Бесплатно. Без подписок. Платишь только 10%, когда получил деньги.*

---

## Ключевые условия

| Параметр | Значение |
|---|---|
| Размещение задания | **0 ₽**, без подписок и платных откликов |
| Комиссия новичкам | **10%** (до 50 000 ₽ заработка) |
| Комиссия опытным | **7%** (от 50 000 ₽) |
| Комиссия ТОП-ам | **5%** (от 300 000 ₽) |
| Минимальный вывод | **100 ₽**, хоть каждый день |
| Комиссия за вывод | 0 ₽ |

Ступень комиссии пересчитывается автоматически по накопленному заработку —
новичок видит цель, а ТОП-фрилансеры не уходят к конкурентам.

---

## Возможности

**Публичная часть**
- Главная с оффером, тарифами «Вариант PRO» и живым тикером
- **Калькулятор комиссии** — слайдеры суммы и ступени, сравнение
  с Kwork (20%) и FL.ru PRO (подписка 2 400 ₽/мес) в месяц
- Лента заданий с фильтрами, поиском, сортировкой и расчётом «на руки»
- Публикация задания за 0 ₽
- Раздел **«Для ИП»** — налоги, документы, сравнение статусов
- Страница **«Документы»** — реквизиты ИП и публичная оферта

**Админ-панель** (`/admin`)
- **Мои заработки** — KPI, график за 6 месяцев, таблицы сделок и выводов,
  виджет вывода от 100 ₽
- **Платёжные системы** — статус LIVE/ДЕМО, тумблеры, webhook-URL
- **Реквизиты ИП** — редактирование с живым превью и валидацией

**Платежи**
- ЮKassa, СБП, Т-Банк, Robokassa
- Встроенная **демо-песочница**: пока ключи не заданы, весь цикл оплаты
  работает на тестовом шлюзе. При добавлении ключей тот же код уходит
  в боевой режим — логика не меняется
- Вебхуки с проверкой подписи (SHA-256 для Т-Банка, MD5 для Robokassa)

## Быстрый старт локально

**Требования:** Node.js 20+, PostgreSQL 14+.

```bash
# 1. Установить зависимости
npm install

# 2. Настроить переменные окружения
cp .env.example .env
# затем укажите свой DATABASE_URL в .env

# 3. Применить схему базы
npx drizzle-kit push --force

# 4. Запустить в режиме разработки
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

> Схема также создаётся автоматически при первом обращении к пустой базе —
> ручной запуск миграций не обязателен.

npm run build      # production-сборка

npm run lint       # ESLint

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `DATABASE_URL` | ✅ да | Строка подключения к PostgreSQL |
| `YOOKASSA_SHOP_ID` | нет | ID магазина ЮKassa |
| `YOOKASSA_SECRET_KEY` | нет | Секретный ключ ЮKassa |
| `TBANK_TERMINAL_KEY` | нет | Ключ терминала Т-Банка |
| `TBANK_PASSWORD` | нет | Пароль терминала Т-Банка |
| `ROBOKASSA_LOGIN` | нет | Логин Robokassa |
| `ROBOKASSA_PASSWORD1` | нет | Пароль #1 Robokassa |
| `ROBOKASSA_PASSWORD2` | нет | Пароль #2 Robokassa |

Без ключей эквайринга приложение работает в демо-режиме —
функциональность полная, платежи проходят через встроенный тестовый шлюз.

> ⚠️ Файл `.env` не коммитится. Он исключён через `.gitignore`.

## Логика комиссии

```ts
// src/lib/commission.ts
TIERS = [
  { name: "Новичок", rate: 10, from: 0,       to: 50_000 },
  { name: "Опытный", rate: 7,  from: 50_000,  to: 300_000 },
  { name: "ТОП",     rate: 5,  from: 300_000, to: null },
]
```

Ступень определяется по суммарному брутто-заработку. При добавлении сделки
сервис автоматически применяет актуальную ставку и пересчитывает баланс —
писать заявки на понижение не нужно.

## Деплой

Полная пошаговая инструкция для Reg.ru + GitHub + Vercel + Neon —
в файле **[`DEPLOY.md`](./DEPLOY.md)**.

Кратко: код на GitHub → база в Neon (Pooled-строка) → импорт в Vercel
→ переменная `DATABASE_URL` → домен в Reg.ru (A + CNAME).

Вебхуки для кабинетов платёжных систем:

```
/api/payments/webhook/yookassa
/api/payments/webhook/tbank
/api/payments/webhook/robokassa
```

## Безопасность

- Данные карт не касаются сервера — обрабатывает банк-эквайер (PCI DSS)
- Вебхуки проверяют подпись, подделанные запросы отклоняются с `403`
- Валидация на сервере: ИНН, ОГРНИП, БИК, номера счетов, суммы
- Реквизиты счетов и БИК проверяются контрольными числами
